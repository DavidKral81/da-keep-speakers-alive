================================================================
  DA KEEP SPEAKERS ALIVE
  Stops your speakers falling asleep and cutting off the start
  of every sound.
================================================================

Powered speakers switch themselves off after a few minutes of
silence, and then swallow the first second or two of whatever you
play next - the start of a video, the first word of a call, a
notification sound.

So this app sends them a SHORT TONE every few minutes, so low and
so quiet that you cannot hear it, yet the speaker recognises it as
a signal.

It does not keep the computer awake and it cannot wake it up. It
runs as an icon next to the clock.

----------------------------------------------------------------
  1. GETTING IT RUNNING
----------------------------------------------------------------

A) THE INSTALLER (the usual way)

Download  DaKeepSpeakersAlive-setup.exe  from the project page
(Releases) and run it. It asks for administrator rights and
installs into  C:\Program Files\Da Keep Speakers Alive.

The setup window lets you choose:

  - a shortcut in the Start menu
  - a shortcut on the desktop
  - starting when you log in to Windows

The language is switched with the flags in the top right corner,
the same as in the app.

To remove it later, use the ordinary Settings -> Apps. The
uninstall window has a "Delete the settings and the log as well"
tick box:

  left off (default)   the settings stay in %APPDATA%, so a
                       reinstall finds everything as it was
  ticked               the settings and log folder goes too

The installer is not signed, so SmartScreen warns the first time -
"More info" -> "Run anyway".

Python does NOT have to be on the machine, it is packed inside.


B) FROM SOURCE (for development)

It needs Python 3.14 and Windows.

  1. In the project folder, create a virtual environment and
     install the dependencies:

       py -m venv .venv
       .venv\Scripts\python.exe -m pip install -r requirements.txt

  2. Run  start.bat

The app has no window on the desktop - only an icon at the bottom
right, next to the clock (possibly hidden under the arrow for
hidden icons).

  start.bat --show     opens the settings window straight away

Where things are kept:

  run from source      settings and log sit next to the sources
                       (windows\config.json, windows\keep_alive.log)
  installed copy       %APPDATA%\Da Keep Speakers Alive
                       (an uninstall leaves them there, so settings
                       survive a reinstall)



----------------------------------------------------------------
  2. QUICK START
----------------------------------------------------------------

  1. Run  start.bat  and click the icon next to the clock. The
     window opens.

  2. Under "Which speakers to keep awake", pick your speakers.
     Either leave "Always the system default device" on (whatever
     Windows is set to right now), or tick a specific output.
     Both at once is fine too.

  3. Click "Try a pulse". You will not hear anything - that is
     the point. A bar under the button shows that the pulse really
     went out. If something went wrong it turns red and the reason
     is up in "Status".

  4. Under "Application behaviour", turn on "Start when I log in
     to Windows".

  Done. From now on a pulse goes out every 3 minutes and the
  speakers have no reason to fall asleep.



----------------------------------------------------------------
  3. THE WINDOW
----------------------------------------------------------------

Opens by clicking the icon next to the clock. Everything is on one
page; when the window is wide, the settings split into two columns
by themselves. The window remembers its size and position.

STATUS
    Whether it is keeping the speakers awake, when the last pulse
    went out (and how long ago), when the next one is due and how
    many there have been since the app started. When the last
    pulse failed, the reason is here.

    "Send a pulse now" sends one out of turn.

WHICH SPEAKERS TO KEEP AWAKE
    Always the system default device
        Sends to wherever Windows is playing right now. Switch the
        output and the app notices on its own.
    The list of outputs
        Tick one or more. A device is remembered by NAME, not by
        position, so the choice survives plugging the USB into
        another port. A device that is not connected at the moment
        stays in the list, marked "(not connected)".
    Reload the list of devices
        For when you have just plugged something in.

HOW OFTEN TO SEND A PULSE
    30 seconds to 15 minutes, 3 minutes by default. The interval
    has to be shorter than the time your speakers take to fall
    asleep. If they still do, shorten it.

    Three things do not wait for the interval and get a pulse
    right away: starting the app (so, logging in to Windows
    too), the computer waking up, and plugging in a speaker you
    picked - they are asleep at all three moments, and waiting
    another fifteen minutes for them makes no sense. A device
    that has just been connected is noticed within 10 seconds. If the pulse cannot be played (the device
    has yet to come back after a wake-up), it is tried again
    after 10, 20, 40 seconds and then three more times a minute
    apart, before going back to the full interval - a device
    that is gone for good must not fill the log for ever. If
    the interval you picked is shorter than one of those waits,
    the interval wins. The "Next pulse" line shows it.

WHAT THE PULSE SOUNDS LIKE
    Frequency, volume, length - see section 5. Plus the "Try a
    pulse" button and the bar under it.

APPLICATION BEHAVIOUR
    Keep the speakers awake          the main switch
    Start when I log in to Windows   see section 7
    Write a log file

LANGUAGE
    The two flags in the top right corner of the window. It
    switches immediately, including the icon's menu. The active
    language is the one with the bar under its flag. The flags
    do not scroll away with the content - they stay in the
    corner.

PAUSE FOR A WHILE
    15 minutes to 8 hours - for when you are recording audio, say.
    It switches itself back on afterwards; neither the window nor
    the menu goes on claiming it is still paused.

At the bottom: a link to the project page and a "Quit application"
button.

----------------------------------------------------------------
  5. WHAT THE PULSE IS
----------------------------------------------------------------

The default is  20 Hz · 1 % · 0.4 s · every 3 minutes.

That is measured, not guessed: at 20 Hz and 1 % the pulse was not
audible in a quiet room, and half that volume was already enough
to keep the speakers from switching off. So the default is twice
what proved necessary - the headroom costs nothing, because you
cannot hear it anyway.

WHAT YOU CAN CHANGE

  Frequency     5 to 100 Hz     the lower, the harder to hear
  Volume        0.1 to 10 %     % of full scale (1 % = -40 dBFS)
  Length        0.1 to 2 s

TWO THINGS WORTH KNOWING

  The edges of the pulse fade in and out. Without that the tone
  would start and end on a step, and a step is broadband noise -
  a click you hear far better than the tone itself.

  A pulse shorter than two full waves is not a tone but a DC step,
  which the speaker's coupling capacitor eats. The window warns you
  as soon as your combination of frequency and length falls below
  that line (5 Hz at 0.2 s, for instance).

IF THE SPEAKERS STILL FALL ASLEEP

  Try these in order, changing one thing at a time:
    1. shorten the interval (3 min -> 2 min -> 1 min)
    2. raise the volume (1 % -> 2 %)
    3. raise the frequency (20 Hz -> 30 or 50 Hz)

  What is verified is that a 3-minute cadence is enough. Whether a
  longer interval would also do was never tested.



----------------------------------------------------------------
  6. IF YOU CAN HEAR IT, OR IF IT CRACKLES
----------------------------------------------------------------

YOU CAN HEAR THE TONE
    Lower the volume first, then the frequency. 20 Hz at 1 % is
    below the threshold of hearing on most speakers; smaller
    speakers cannot reproduce low tones anyway.

IT CRACKLES
    The app keeps a 100 ms audio buffer of its own and waits for
    the sound to drain before closing the stream. Left to Windows
    the buffer comes out at about 20 ms, and a buffer that short
    crackles all the way through the tone, whatever the volume and
    whatever the frequency. That is why the app sets it itself.

    If it still crackles, lower the volume: a low tone played
    loudly asks a small speaker for more cone excursion than it
    has.



----------------------------------------------------------------
  7. STARTING AT LOGON
----------------------------------------------------------------

Turned on in the window, under "Application behaviour". It creates
a task in Windows Task Scheduler named "Da Keep Speakers Alive":

  - starts at logon, with no delay (the speakers have been
    asleep since the machine was switched off, so that is
    exactly when they need the pulse)
  - restart on failure: after 1 minute, at most 3 times
  - no execution time limit (otherwise Windows would kill it after
    3 days)
  - runs on battery too
  - DOES NOT WAKE the computer (the task has no time trigger and
    "wake the computer to run this task" is off - this app must
    never be a reason for the machine to switch itself on)

Turning the switch off deletes the task.

If the task cannot be created (permissions, say), the app SAYS SO
and the switch stays off. Nothing is substituted on purpose -
quietly dropping a shortcut into the Startup folder instead would
mean doing something other than what you asked for.

The app CANNOT run as a Windows service. Services run in session 0,
where audio does not physically play. It has to be an ordinary user
process - which also means a locked screen or a blanked monitor
changes nothing, because neither ends your session.



----------------------------------------------------------------
  8. WHEN SOMETHING DOES NOT WORK
----------------------------------------------------------------

Look at "Status" in the window first, then at keep_alive.log
(section 10 says where it is). The log is always in English.

  "Device ".." is not connected."
      The chosen output is not in the system right now. Plug it
      in, pick another one in the settings, or turn on "Always the
      system default device". The typical case: speakers on a dock
      the laptop has been unplugged from.

  "No device is selected"
      "Always the system default device" is off and nothing is
      ticked in the list.

  The speakers still fall asleep
      Shorten the interval, then raise the volume - see section 5.

  The pulse is audible, or it crackles
      See section 6.

  The icon is not there
      It will be hidden under the arrow for hidden icons at the
      bottom right.

  The app will not start twice
      That is correct - the second attempt only says it is already
      running.

  A speaker is missing from the list
      "Reload the list of devices". The list is also re-read before
      every pulse, so a newly plugged-in output is noticed at the
      next pulse at the latest.



----------------------------------------------------------------
  9. SETTINGS IN THE FILE
----------------------------------------------------------------

The file  config.json  in the data folder. Everything except one
item is easier to set in the window; only this one is changed in
the file, and the app has to be restarted afterwards:

  fade_s     how long the edges of the pulse take to fade in and
             out (0.05 s by default). Deliberately not in the
             window - whoever understands it will find it here,
             and whoever does not would only gain a way to make
             the pulse click.

The other keys match the items in the window.

The file is read even with a BOM (Notepad adds one), and written
without one. If it is damaged, the app uses the defaults and says
so in two places: in the log, and in the window, on the
"Application behaviour" card. Mind that your choice of speakers is
not among the defaults - if that message shows up, have a look at
config.json.

----------------------------------------------------------------
  11. FOR DEVELOPMENT
----------------------------------------------------------------

COMMAND LINE SWITCHES

  start.bat --show            open the window straight away
  start.bat --pulse           one pulse, then quit (a quick check
                              with no window)
  start.bat --autostart-on    turn on starting at logon
  start.bat --autostart-off   turn it off
  start.bat --quit-after N    quit on its own after N seconds
                              (for the tests)
  start.bat --no-dialog       never show a message box (tests)

THE MEASURING RIG

  tune.bat --list
      lists the outputs with their numbers

  tune.bat --tone --device 23 --freq 20 --amp 1.0 --repeat 3
      plays the tone - can you hear it?

  tune.bat --keepalive --device 23 --freq 20 --amp 1.0
           --interval 180 --minutes 20
      runs a keep-alive cycle for as long as you say

  tune.bat --check --device 23
      plays a series of audible beeps. However many are missing
      from the start is how many the speaker slept through.

  The measuring procedure: --check after ten minutes of silence
  (how many beeps are missing?) -> --keepalive for 20 minutes ->
  --check again straight afterwards (do you hear them all now?).

TESTS - RUN BEFORE EVERY RELEASE

  .venv\Scripts\python.exe tests\test_logic.py
      the pulse, the bar, device matching, the settings file, texts

  .venv\Scripts\python.exe tests\test_window.py
      branches normal use never reaches (language switch, pause,
      mouse wheel, closing twice)

  .venv\Scripts\python.exe tests\test_window.py --break-it
      puts five real, previously-shipped bugs back in - the run
      MUST fail. A check nobody ever tried to break reads exactly
      like a check that does not work.

  .venv\Scripts\python.exe tests\test_installer.py
      the whole install/uninstall cycle. Every target is
      redirected into a temp folder and an HKCU key, so it needs
      no administrator and never touches a real installation. It
      REFUSES to run while the app is up - it stops whatever holds
      the app's lock, and that would be your own copy. Quit it
      first.

  .venv\Scripts\python.exe tests\preview.py
      renders the window to PNG into _output\ - then look at it
      with your own eyes, in both languages and at both widths.

  .venv\Scripts\python.exe tests\preview.py --installer
      the same for the setup windows. A user sees those once and
      never again, so nobody would notice they look wrong.

WHILE THE APP IS RUNNING IT HOLDS THE PROJECT FOLDER. Quit it
before renaming or moving the folder (icon menu -> Quit
application). The .venv virtual environment breaks when the folder
is renamed - delete it and create it again.
